## Now

App is a Spanish Blazor Server UI over `FachadaAplicacion`. Catalog access is local, remote (REST) or SOAP via `Catalogo:Modo`. Docker Compose defaults to `Soap`: parts by SOAP, vehicle options and AI by REST.

Run: `docker compose up --build --wait` → web `http://localhost:8080`, catalog `http://localhost:8081/salud`, SOAP `http://localhost:8082/ConsultaCompatibilidad.svc?wsdl`, Postgres `localhost:5432`.

Tests: `docker compose --profile test build tests && docker compose --profile test run --rm tests` is the canonical verification. Without the build step, `run` reuses an old `repmatch/tests` image and reports a stale count.

Messaging implemented 2026-11-11 (Segunda Parte, issues #12, #13 and #14, branch `feature/mensajeria-rabbitmq` stacked on `feature/ofertas-vtex`). `IEventBus` and versioned `MensajeIntegracion<T>` contracts (`*V1`, ids only, never the free text) in Contracts. New library `RepMatch.Mensajeria` on `RabbitMQ.Client` 7.2.2: `BusRabbitMq` (persistent messages, publisher confirms, correlation id in the body and as AMQP header), `ConexionRabbitMq` (one lazy connection per process, automatic recovery, 30 s pause after a failed connect so a down broker costs one timeout, not one per click), `TopologiaRabbitMq` (topic exchange `repmatch.eventos`, dead-letter exchange `repmatch.eventos.dlx`, durable queue + `.dlq` per consumer) and `ConsumidorRabbitMq<T>` (ack after processing, one requeue, then DLQ; unreadable → DLQ). `BusRabbitMq` declares the shared consumer topology before its first publish, publishes as mandatory, and logs returned unroutable messages. `PublicadorEventos` is a second observer registered after `ObservadorCompatibilidad`; broker failures are logged and never break the user action. `BusDesactivado` when `Mensajeria:Habilitada=false` (default outside Docker). New host `RepMatch.Notificaciones.Worker` (port 8085): `ConsumidorComisiones` (`repmatch.comisiones` ← `derivacion.tienda` → `ComisionesTienda` per store and month, idempotent through `mensajes_procesados` in the same transaction) and `ConsumidorActividad` (`repmatch.actividad` ← `#`, log only); `/salud` and `GET /api/comisiones`. `ContextoCorrelacion` (AsyncLocal, set by `CorrelacionMiddleware`) carries the id to the publisher. Compose adds `rabbitmq` (4-management, fixed hostname, volume, user `repmatch`) and `worker`; the Web does not wait for the broker. Notifications to client and mechanic, and fetching prices from the worker, are not built: they would be new consumers. No outbox: a message published while the broker is down is lost (the fact stays in the database).

**PostgreSQL schema updates use EF Core migrations.** The initial migration represents the schema before messaging; the next adds `comisiones_tienda` and `mensajes_procesados`. Existing volumes created by `EnsureCreatedAsync` are adopted only when all initial tables are present; the advisory lock serializes adoption, migration and seeding across hosts. InMemory continues using `EnsureCreatedAsync`.

## Gotchas

- `clientes.VehiculoPredeterminadoId → vehiculos` (SET NULL) plus `vehiculos.ClienteId → clientes` (CASCADE) is an FK cycle. EF cannot order a single INSERT or DELETE of both rows (`circular dependency` on Postgres; InMemory does not notice). Seed saves the default in a second `SaveChanges`; `EliminarCuentaAsync` clears the default first inside `IUnitOfWork.EjecutarEnTransaccionAsync`.
- `busquedas.ClienteId` has no FK; account deletion removes them explicitly via `IBusquedaRepository.EliminarPorClienteAsync`.
- `busquedas.MecanicoId` and all `derivaciones` FKs are absent on purpose. Deleting a mechanic unshares their unreviewed searches; reviewed ones keep the review. Derivations survive any deletion (they are the commission record).
- Behind the BNA corporate proxy, Docker injects the proxy into builds and running containers. Builds fail at `dotnet restore` (`NU1301`, `PartialChain`) because the proxy re-signs TLS with the `BNA-SG` CA that WSL trusts but the SDK image does not. At runtime, the injected `NO_PROXY` lacks `catalogo-api` (and now `ia-api`), so Remote mode sends Web → API calls to the proxy (404/407) and a search crashes the circuit. The 2026-11-03 and 2026-11-05 runs used, outside the repo, Dockerfile copies that add the CA and a compose override that adds `catalogo-api,ia-api,postgres` to the Web's `NO_PROXY`. The repo files are unchanged.
- RabbitMQ keeps its data per node name: compose fixes `hostname: rabbitmq`. Without it the `datos-rabbitmq` volume is not recognised after the container is recreated and durable queues are lost.
- The worker does not create the schema: in compose it waits for `catalogo-api` to be healthy. Run on its own against an empty Postgres, `comisiones_tienda` does not exist yet.
- Driving Docker from Windows with one-shot `wsl -e …` calls: the WSL instance stops once no process is left, despite `instanceIdleTimeout=-1` in `.wslconfig`, and takes the containers with it (they show `Exited (0)`). Keep a `wsl -e sleep infinity` running while testing.
- `AccesoLocalVsRemotoTests` and `AccesoSoapTests` host `Catalogo.Api` and `Catalogo.Soap`, which seed the same InMemory database (`"repmatch"`) on startup. Run in parallel, both could see it empty and duplicate the catalog (intermittent failure since the SOAP host was added). They share the xUnit collection `ColeccionBaseCompartida`; any new test that hosts a seeding app must join it.
- EF owned types cannot share one `DatosVehiculo` instance between two `Busqueda` rows: tests seeding several searches must use a fresh instance each (`Gol with { }`).
- `SesionActual.RefrescarAsync()` reloads the client and fires `Cambio`; Home only resets its form when the client id changes, so a theme toggle does not clear results.
- Do not change the `@key` of the `InputFile` while a file is being read: the input element is replaced and reading fails.
